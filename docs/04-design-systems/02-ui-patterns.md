# UI Patterns

Here's your scenario.

Orbit needs users to choose their university year: `Year ???`

You could use:

- Dropdown 
- Radio buttons
- Text input
- Stepper

All technically work.

## Ask the right questions

Instead of *"Which looks prettier?"*

Ask ***"Which interaction makes sense?"***

If there are only four options:

```
○ Year 1
○ Year 2
○ Year 3
○ Year 4
```

might be easier than hiding them behind a dropdown. **This is a UI pattern decision.**

## Component vs Pattern

|Category|Definition|Examples|
|--------|----------|--------|
|Component|*Individual reusable building block*|Button, Input, Checkbox, Modal|
|Pattern|*Multiple elements working together to solve a recurring user problem*|Login form, Search experience, Checkout, File upload, Challenge|

> Note: Notice the boundaries aren't always perfectly rigid. That's normal. Design isn't taxonomy homework.
